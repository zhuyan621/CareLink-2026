使用说明，

本页的自然语言分析、护理交接、两种糖尿病研究计算、医学问答与盲评，共用以下规则。

01 / 能做什么

完整基线信息可调用 MAPFM TFA 权重，估计未来 3 年新发糖尿病研究风险；另有独立的 Framingham 8 年发表评分。英文医学知识问题进入 MedQuAD 来源检索。其他疾病、缺失指标或矛盾输入不生成概率。

02 / 如何输入

只用合成或充分脱敏的资料，不填写姓名、联系方式、病历号或真实患者交接记录。案例库最多 10 个（6 个预置、4 个自建）；输入改变后旧筛查与复核失效。已确诊糖尿病或数值超出对应模型范围时，系统会拒绝计算。

03 / 如何看结果

3 年权重来自日本公开队列，8 年评分来自美国发表规则，均未在中国目标人群独立外部验证；心率、血氧等交接体征不参与这两项糖尿病计算。百分比不是个人诊断概率，问答检索相关度也不是医学准确率；历史自检快照不代表此刻在线。

04 / 如何盲评

题包与标注只在本机浏览器读取、下载，不会由盲评页自动上传。建议两名医学背景审核者独立标注、分歧交由第三人裁决；分享文件前人工检查是否含个人健康叙述，不要上传第三方网站。

本系统仅供科研与竞赛演示，不用于诊断、分诊或个人医疗决策。急性警示症状应按所在地机构流程由专业人员处理。

    01这能直接用于真实临床诊断或分诊吗？+

    不能。项目目前是科研与竞赛演示原型，没有独立外部临床验证，也没有医疗使用资格。优先级仅为演示线索，最终判断由具备资质的专业人员承担。

    02动态证据为 0，为什么还能显示离线信息卡？+

    两者来源不同。动态检索只有通过来源核验才计入动态证据；离线公共信息卡由人工整理并独立标记，不能冒充本次实时检索结果。

    03“Ollama 最近自检成功”意味着现在在线吗？+

    不意味着。证据板读取的是带时间戳的历史快照；当前服务状态必须以工作台本次实际运行的结果为准。

    04案例与页面数据是否来自真实患者？+

    工作台六个案例均为合成演示，其中三组单次体征取自演示样本表；另有 605 条问答索引仅供资料核对，不是患者记录。请勿在演示中输入姓名、联系方式、病历号或其他可识别个人信息。

    EXECUTION / 必须以接口回执为准

    运行的是工程，
    不是一张结果图片。

    在工作台点击运行后，记录进入预处理与 MAPFM 协作链；DMA 按配置调用本机推理服务。

    1. 检查本机服务和推理后端是否可用。
    2. 读取本次请求的执行轨迹与生成状态。
    3. 如果后端失败，查看明确的失败或降级提示，不把降级文本当作正常推理。
    /screening/engineering → MAPFM → DMA
    TRACEABILITY / 来源不等于有效性

    每条线索，
    都值得追问出处。

    检索、融合和来源核验分别保留职责。查看本次返回的来源标识、核验状态、拒绝原因与未解决的信息缺口。

    1. 区分动态返回的资料与预置离线材料。
    2. 核对可追溯标识和来源是否与问题相关。
    3. 即使有出处，医学适用性也仍需专业人员判断。
    RAA → Fusion → Verification
    HUMAN REVIEW / 不自动放行

    流程的下一步，
    必须有人负责。

    该合成案例设置强制人工接管，用来检查系统能否把需要复核的信号交给使用者，而非自动作出临床决定。

    1. 阅读本次结果、限制与来源状态。
    2. 在工作台填写复核决定及说明。
    3. 是否处置、升级或补充观察，由专业人员负责。
    Consensus → 人工复核记录
    RECORD / 把过程留下来

    留下记录，
    也留下它的边界。

    1. 检查导出内容是否对应本次输入与复核。
