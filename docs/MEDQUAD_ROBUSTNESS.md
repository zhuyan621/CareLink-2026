# MedQuAD 自然问法与上线门禁｜2026-10-12

## 这次真正改变了什么

增加了自然语言提问的开发／封存评测、候选重排实验和上线门禁。**线上检索排序最终没有更换**：候选方案在开发题上略好，但封存题退步，因此拒绝上线。这是一次有否定结果的工程验收，不能写成模型泛化性能已经再次提升。网站展示两个不同测试口径，并公开这一否定结果。

## 数据与切分

使用 TREC 2017 LiveQA 医疗任务的 2 份公开训练题镜像（原始数据集 [CC BY 4.0](https://github.com/abachaa/LiveQA_MedicalTask_TREC2017)）。镜像来自 [Hugging Face 数据集](https://huggingface.co/datasets/hyesunyun/liveqa_medical_trec2017)，文件 SHA-256 记录于 `artifacts/medquad_qa/robustness_audit.json`。选择条件：外部参考答案的前 120 个规范化字符与 MedQuAD 中有答案记录完全一致；问题长度 5–500 字符；原问句不得与 MedQuAD 原问句完全重复。得到 80 个自然问法。按问题 SHA-256 首字节预先分为开发集 42 题和封存集 38 题。

镜像原文含公开的个人健康叙事；为最小化传播，**交付 ZIP 不含原始镜像问题**，只含聚合评测报告及复现脚本。复现时从报告里的两个镜像 URL 下载到 `artifacts/medquad_qa_candidate/liveqa_train1_mirror.jsonl` 与 `liveqa_train2_mirror.jsonl`，先核对 SHA-256，再运行 `python medquad_holdout.py --split development`。复现不等于重新调参；已使用的封存集不能再用于下一版参数选择。

## 结果与决策

| 检索排序 | 开发集已知答案 Top-3 | 封存集已知答案 Top-3 | 封存集已知来源 Top-3 |
| --- | ---: | ---: | ---: |
| 当前交付版 | 45.24% | 42.11% | 55.26% |
| 移除人工来源加分候选 | 47.62% | 36.84% | 52.63% |

两版在封存集的第一名已知答案命中均为 28.95%，回答率均为 71.05%；10 条预定义非医学问题均拒答。通用 `ms-marco-MiniLM-L6-v2` 交叉编码重排器在开发集第一名已知答案命中由 33.33% 降到 21.43%，Top-3 未提高；焦点／意图加分也没有稳定收益，所以两者都不接入产品。原有**排序逻辑**已还原；`medquad_qa.py` 因增加审计状态字段而与上一交付版文件哈希不同。打包和状态接口会核对本版源码哈希与拒绝决策。

这里的“已知答案”仅指上述严格文本对齐的正例；未标注回答不视为错误。来源答案本来就位于 MedQuAD 索引，测试的是用户问法变化下的检索，不是对新疾病、未来糖尿病发病、临床诊断或答案时效性的验证。封存集只有 38 题，已经用于这次上线决策；下一次提高泛化应另找新数据并冻结评测规则后再试验。

## 可复现文件

- `medquad_holdout.py`：外部自然问句、答案前缀对齐、固定切分、实际 `ask()` 端到端检索与越界问题测试。
- `artifacts/medquad_qa/robustness_audit.json`：数据哈希、两个切分的关键汇总、否定的上线决策。
- `medquad_generalization.py` 与 `artifacts/medquad_qa/generalization_benchmark.json`：较早的 LiveQA 测试问法不完整标注评测。它不是本轮 80 个自然问法的替代品。

真正的下一步是新增未参与本轮的医学问答来源、由医学专业人员盲评答案质量，并对疾病类别、资料来源、问法长度和拒答错误逐层报告；糖尿病发病预测要另做外部纵向队列与校准验证。
